MRL #146 Briefing

SoP run as written (Tables 3–5, version_minor slot rule, w = 16, k = 3, d = 5 s) in monerod v0.18.5.1 under the Shadow network simulator: 12 daemons, real RandomX, 120 s blocks. Every fork-choice decision is logged and re-derived by an independent checker: 43,949 decisions, 0 mismatches. The attacker withholds, reveals once its branch holds 48 work objects and outweighs the honest chain, and gives up when honest leads by d blocks.

Two questions about the spec

Q1 · Which n_f is intended?

The issue gives two rules that are not the same:

Formal: n_f counts work objects in the alt chain "not contained in the main chain".
Prose: the lateness factors apply only if "the two chains differ by fewer than k*w work objects".

Under the formal reading, which branch is the alt one decides whether a comparison is subjective (receive times count) or objective. Under the prose reading, a pair is objective as soon as either side holds k·w = 48 objects. We implemented the formal reading.

Q2 · What happens to blocks displaced by a reorg?

The spec doesn't say. Stock monerod pushes every displaced block back through the fork choice after a reorg (blockchain.cpp:1163–1180). Under cumulative difficulty that check can never win. With SoP weights it can.

Why it matters: one pair, both directions say SWITCH

An honest block H with 11 workshares, all gossiped early, against 7 attacker blocks A1–A7, each with 8 workshares that were never gossiped.

n_f counts the alt side only, and lateness is timed against whichever block is main at each height, so the answer depends on which branch the node is already on. We saw this live: alt 4234/6 vs main 3796/4 → SWITCH, then 1 ms later alt 1022/1 vs main 438/6 → SWITCH. Under the prose reading the pair is objective in both directions once the attacker's side holds 48 objects, and the flip can't happen.

Options we see, none chosen:

  • Judge each pair symmetrically (the prose reading of n_f).
  • Judge a displaced branch again only when a new block extends it (our simulator's default).
  • Say in the spec that a reveal that won is final until the losing branch is extended.

Even with our default, 7 of 367 reveals in the 240 h runs (2 %) were reversed within 3.3 s, each by one honest block that made the honest branch heavier. In 3 of the 7 the honest branch was still the shorter one. This is albinjm's question 1, seen at near-zero network delay.

Numbers not to quote. In runs where monerod re-checked displaced blocks, the attacker's share came out near zero. That is an accident of monerod's code: the switch back runs inside the first switch, the duplicate check (:2073) refuses to store the attacker's blocks again, and the outer switch deletes them (:1182–1186). It says nothing about SoP.

SoP is a hard forkversion_minor rule

The spec puts the workshare count in version_minor, which v0.18 uses as the hard-fork vote and requires to be at least 16 (hardfork.cpp:109–113). Honest blocks carry about 15 workshares on average, median 11, so most SoP blocks look like an old version to an unupgraded node.

Seen directly: an unmodified node rejected SoP blocks with "has old version" (blockchain.cpp:1889). Another field or an offset encoding would avoid it.

Peer bansstock P2P scoring

SoP nodes legitimately switch to a branch with fewer blocks. Stock monerod scores a peer whose reported height drops (hit_score), and the fail score never decays, so honest nodes ban each other for 24 h.

With a depth-5 attacker: bans in 3 of 5 runs (48, 57 and 10); one relay stuck on a stale branch for 13.7 simulated hours. Replaying the fail score from the logs predicts all 67 bans. Not scoring height drops gave 0 bans in three 240 h re-runs; that fix is blunt and a deployment would want a narrower rule.

Limits

  • 12 daemons, two honest miners, fast propagation. Realistic delay and many pools are not tested.
  • One attacker design. It is not tevador's T5 attacker, which gives up in objects and uses honest workshares in its first private block.
  • α = 0.40 rests on 6 h runs. α = 0.45 is not established: three 6 h runs gave 0.22, 0.47 and 0.43, too noisy to tell from α (a race model gives 0.36).
  • Three seeds, and we haven't verified that a seed fixes network placement. The ban fix is untested at scale.
